# Power Monitor — мониторинг наличия электричества на ESP32 / ESP8266

Небольшое устройство на ESP, которое питается от сети 220 В (через обычную USB-зарядку) и раз в минуту отправляет «пульс» в Google Apps Script. Скрипт ведёт журнал включений и отключений в Google Таблице и присылает уведомления в Telegram:

- 🔴 **Электроэнергия отключена** — сигнала нет дольше 4 минут;
- 🟢 **Электроэнергия восстановлена** — с длительностью отсутствия;
- 🟡 **Сигнал восстановлен без отключения питания** — пропал интернет или Wi-Fi, а не свет.

Облачная часть работает на бесплатном аккаунте Google, отдельный сервер не нужен.

## Как это работает

```
ESP ──POST {"boot_time": …} раз в минуту──► Google Apps Script (веб-приложение)
                                                │            ▲
                                                ▼            │ триггер раз в 5 мин
                                       Google Таблица "Log"  │ (проверка тайм-аута)
                                                │
                                                ▼
                                         Telegram-бот
```

`boot_time` — момент включения питания (Unix-время, из NTP). Пока он не меняется, скрипт считает, что это одна сессия, и обновляет время последнего сигнала. Новое значение означает, что питание пропадало и вернулось: добавляется новая строка. Если плата перезагрузилась программно (потеря Wi-Fi, сторожевой таймер, обновление прошивки), `boot_time` сохраняется в RTC-памяти и не даёт ложного «отключения света».

Журнал в таблице (новые записи сверху):

| Включено | Выключено | Длительность | Отсутствие |
|---|---|---|---|
| 25.11.2026 08:15 | 25.11.2026 14:02 | 5 ч. 47 мин. | 0 ч. 00 мин. |

«Выключено» — время последнего полученного сигнала, «Отсутствие» — сколько света не было *после* этой сессии.

## Что нужно

- плата ESP32, ESP32-C3 или ESP8266 (ESP-12E / NodeMCU);
- USB-зарядка (5 В), включённая в проверяемую розетку;
- аккаунт Google и Telegram-бот;
- [PlatformIO](https://platformio.org/) (VS Code или CLI).

## Структура проекта

## Установка

### 1. Google Таблица и скрипт

1. Создайте Google Таблицу.
2. Откройте **Расширения → Apps Script** и вставьте содержимое `google/Code.gs` в один файл `Code.gs` (старые файлы удалите).
3. Настройки находятся в самом начале файла: название листа, часовой пояс, тайм-аут, тексты уведомлений.
4. Создайте Telegram-бота у [@BotFather](https://t.me/BotFather), узнайте свой chat ID (например, через @userinfobot) и укажите их:
   - `TG_CHAT_ID` — в коде;
   - токен бота лучше положить в **Настройки проекта → Свойства скрипта** под именем `TG_BOT_TOKEN` (или вписать в константу `TG_BOT_TOKEN`, но тогда не публикуйте файл с настоящим токеном в репозиторий).
5. Запустите функцию `setupSheet()` и выдайте разрешения. Она оформит лист `Log`, пришлёт тестовое сообщение и создаст триггер (проверка раз в 5 минут).
6. **Развёртывание → Новое развёртывание → Веб-приложение**: выполнять от своего имени, доступ — «Все». Скопируйте URL вида `https://script.google.com/macros/s/…/exec`.

> После любого изменения кода скрипта нужно заново создавать *новую версию* развёртывания, иначе работает старый код.

### 2. Прошивка

1. В `src/main.cpp` при необходимости поменяйте имя в сети `MDNS_HOST` и укажите репозиторий для обновлений `GITHUB_REPO` (см. ниже).
2. Первую прошивку делайте по USB:

   ```bash
   pio run -e esp32 -t upload        # или esp32c3 / esp12e
   pio run -e esp32 -t monitor
   ```

3. При первом запуске плата создаст точку доступа **Power-Monitor-Setup**. Подключитесь к ней, выберите свою Wi-Fi сеть и вставьте URL веб-приложения Google в поле *Google Script URL*.
4. Дальше устройство само подключается к сети, синхронизирует время и шлёт сигнал каждую минуту.

### Сброс настроек

Нажмите кнопку **Reset три раза подряд** (каждое следующее нажатие — в течение секунды после предыдущего). Wi-Fi и URL будут стёрты, плата снова откроет точку доступа.

## Индикация светодиода

Светодиод горит при низком уровне на пине (настраивается константой `LED_ACTIVE_LOW`).

| Состояние | Светодиод |
|---|---|
| Нет связи / открыт портал настройки | горит |
| Ожидание синхронизации времени | мигает |
| Всё работает | погашен |
| Идёт обновление прошивки | горит |

## Веб-страница устройства

После запуска страница доступна по адресу `http://power-monitor.local` (или по IP, он выводится в Serial). Страница показывает время включения питания, как давно оно есть, результат последней отправки в Google и счётчики, параметры Wi-Fi, версию прошивки, статус обновления и свободную память. Кнопка «Проверить и обновить» запускает обновление вручную.

Если `.local` не открывается (часто на Android), заходите по IP-адресу.

## Обновление прошивки через GitHub

Устройство проверяет последний релиз репозитория через GitHub API (через 2 минуты после старта, затем раз в 6 часов). Если версия новее установленной, оно скачивает файл `firmware-<env>.bin` из релиза и перезагружается.

Настройка:

1. В `main.cpp` укажите `GITHUB_REPO = "owner/repo"`. Репозиторий должен быть **публичным**.
2. Опционально: `AUTO_UPDATE_CHECK`, `AUTO_INSTALL_UPDATES` (`false` — только уведомлять, ставить по кнопке), интервалы проверки.
3. Выпускайте версию тегом:

   ```bash
   git tag v1.0.1
   git push origin v1.0.1
   ```

   Workflow `release.yml` соберёт прошивки для `esp32`, `esp32c3` и `esp12e`, подставит версию из тега в `include/version.h` и приложит `firmware-esp32.bin`, `firmware-esp32c3.bin`, `firmware-esp12e.bin` к релизу.

Версии сравниваются как `MAJOR.MINOR.PATCH`; установка происходит только на более новую.

Для ESP32 в `platformio.ini` используется схема разделов `min_spiffs.csv` (две OTA-партиции побольше), поэтому первую прошивку нужно делать по кабелю.

## Параметры

| Где | Параметр | Назначение |
|---|---|---|
| `main.cpp` | `HEARTBEAT_INTERVAL_MS` | период отправки сигнала (60 с) |
| `main.cpp` | `WIFI_LOST_REBOOT_MS` | через сколько без Wi-Fi перезагружаться |
| `main.cpp` | `PORTAL_TIMEOUT_S` | сколько держать портал настройки |
| `main.cpp` | `MDNS_HOST` | имя в сети |
| `main.cpp` | `GITHUB_REPO`, `AUTO_*` | обновление по воздуху |
| `Code.gs` | `HEARTBEAT_TIMEOUT_MIN` | через сколько минут без сигнала считать свет отключённым |
| `Code.gs` | `TRIGGER_EVERY_MIN` | частота проверки тайм-аута |
| `Code.gs` | `TIMEZONE`, `DATE_FORMAT` | часовой пояс и формат даты |
| `Code.gs` | `MSG` | тексты уведомлений |

Обнаружить отключение можно не раньше, чем через `HEARTBEAT_TIMEOUT_MIN` плюс период триггера (по умолчанию 4–9 минут).

## Ограничения и безопасность

- **Роутер и интернет.** Если роутер не на резервном питании, то при отключении света пропадёт и интернет, и сообщения о восстановлении придут уже после включения. Пропажа интернета при наличии света распознаётся по неизменному `boot_time` и помечается 🟡.
- **TLS без проверки сертификата.** Устройство использует `setInsecure()`: данные шифруются, но подлинность сервера не проверяется. Для сигналов о наличии света это приемлемо, для чего-то более серьёзного — нет.
- **Веб-страница без пароля.** Любой в вашей локальной сети может открыть страницу и запустить проверку обновлений.
- **URL веб-приложения — секрет.** Любой, кто его знает, может отправлять в таблицу сигналы. Не публикуйте его.
- **Токен Telegram** не коммитьте в репозиторий. Если он случайно попал в публичный доступ, перевыпустите его командой `/revoke` у @BotFather.
- **Нет автоотката.** Если новая версия прошивки не запускается, плату придётся перепрошить по USB.
- **ESP8266.** Памяти у неё мало, и HTTPS-загрузка обновлений с GitHub на ней работает менее надёжно, чем на ESP32.

## Поиск неисправностей

| Симптом | Что проверить |
|---|---|
| Плата всё время в режиме точки доступа | Wi-Fi недоступен или введён неверный пароль; через 3 минуты она перезагрузится и попробует снова |
| В Serial `Skipped! Script URL is empty` | Не введён URL: сбросьте настройки тройным Reset |
| HTTP-код 401/403/404 при отправке | Неверный URL или у веб-приложения не выставлен доступ «Все» |
| Таблица не обновляется после правок кода | Не создана новая версия развёртывания |
| Нет уведомлений в Telegram | Токен и chat ID; напишите боту `/start`; смотрите **Выполнения** в Apps Script |
| Статус «Релизы не найдены (HTTP 404)» | В репозитории нет опубликованного релиза или он приватный |
